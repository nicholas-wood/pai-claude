LIMSOC Permission Assist runs at https://permissions.poc.nicholaswood.com.au from the private repo `nicholas-wood/poc-permissions` (no standing local checkout; clone over ssh). Platform-level facts are in [[project-lsv-poc-platform]].

- **Page source is in `page/`** (`src/app.js`, `src/page.html`, `data/`, vendored xlsx, `build.py`), moved in on 2026-11-23 on Nick's instruction. `python3 page/build.py` writes `site/index.html`, `site/vendor/` and the `files` hashes in `poc.json`; `--check` verifies. Never hand-edit `site/`: `test/page.test.ts` and CI's `verify-site.ts` fail on drift. After changing group names or the snapshot, also run `bun page/make-test-csv.ts`.
- **Reference group is "Superuser (Do not update manually)"** (renamed 23 Nov from "Superuser (last run)"). Nick confirmed no old-named group was ever imported into LIMSOC, so the old name is deliberately not recognised. The phrases "at last run" / "since the last run" were left because they describe the previous run, not the group.
- **Hand-edit detection, shared** (PR #4 browser-only, live as edd3339; PR #6 shared, merged 6e28a74, live since release v0.2.0 on 23 Nov; `/api/health` now reports the release version, not a commit id). Nick: "I need it to call out a group edited by hand in LIMSOC", then "Yes I would like it shared". The page keeps one last-seen record (last uploaded export, replaced by the expected post-import state when an import file is downloaded, with who and when) and on upload lists per group what was added or removed in LIMSOC. On the host it lives in the storage bridge: `window.claude.storage`, shared key `lsvperm-seen`, stored as a JSON string (about 130 KB; bridge limit 500 KB; a string avoids Firestore's per-document index-entry limit). `poc.json` declares capabilities `storage` and `user` and `dataModel: server-only`; `poc.config.json` must list the same capabilities because it switches the bridge on. As a local file it uses localStorage. Because the bridge defines `window.claude`, the page tells host from Claude by hostname (`HOSTED`); without that, downloads break. Only tested against a harness using the repo's real bridge script, not the live host. Adding groups (Nick, 25 Nov: add only, "the other two can stay in LIMSOC"): PR #7 opened, CI green, left for Nick to merge, then the release PR. Step 3 name box plus optional "starting with" another group; added groups always go into the import file unless unticked, kept per export file in localStorage `lsvperm2:<sig>:added`, removable while page-only. LIMSOC creating a group on import is assumed from the reference-group behaviour, not tested by me. Rules and column order match names without the `25-26-` prefix; a new group outside the spreadsheet order is not part of Communications Duty Officer's "every other group" rule.
- **Leave the scaffolded parts alone**: template host files, `vendor/poc-auth`, `infra/modules/poc-app` and the workflows are copied from `lsv-poc-platform`; changes to those go through the platform thread.
- **Shipping**: branch, PR, conventional commit (`feat:`/`fix:`), Nick or I merge on his say-so. PRs #1 and #4 deployed on push. Release-please landed on main (b735e05) right after #4 on 23 Nov, so from then a merge to main does not deploy; merging the release PR does (Nick merges those). Check `/api/health` version before saying a change is live.
- **Verification limit**: `/api/health` reports the deployed commit, but I cannot do a signed-in check there without minting a session in `lsv-poc`, which I have not been given. Test the rebuilt page locally in headless Chrome (file URL plus the test csv) and ask Nick to confirm the live page.
- The page never calls LIMSOC; import testing is Nick's, on staging.limsoc.com.au only. Wording: "members", not "staff".
